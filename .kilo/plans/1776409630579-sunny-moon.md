# Remediation Plan: Audit Findings to PASS

## Goal

Remediate the audited correctness, lifecycle, validation, documentation, and dead-code issues until the repository reaches `VERDICT: PASS` under code review and project verification.

Success means:

- all confirmed bugs are fixed or intentionally eliminated by removing dead code
- every fix is covered by targeted regression tests
- stale docs are aligned with the implemented behavior
- dead-code outputs are reviewed and reduced where safe
- verification passes end-to-end: typecheck, test, build, served smoke, dead-code audit

## Baseline Assumptions

- The prior audit move is already done: `docs/physics/alignment-audit.md` -> `docs/deprecated/physics/alignment-audit.md`
- Current baseline is green on `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm smoke:served`, and `pnpm audit:deadcode`
- The biggest remaining work is logical correctness and missing regression coverage, not broken CI
- Minimal, surgical changes are preferred over large architectural rewrites

## Core Execution Rules

1. Work test-first for each bug cluster.
2. Keep one active bug cluster at a time.
3. After each cluster:
   - run the relevant focused tests
   - run `pnpm typecheck`
   - if the change touches shipped behavior, run `pnpm test`
4. Do not stop at green tests if a finding remains unaddressed.
5. If a file is confirmed retired and unused, prefer deletion over preservation.
6. End with a full verification pass and a final diff review.

## Issue Inventory

### Confirmed correctness bugs

1. Non-browser import path still crashes because `src/main.ts` imports bootstrap unconditionally and bootstrap pulls `uiRefs` at module scope.
2. Disabling the moon can leave stale `moonPhaseCurve` and `dynamics.nbodyPlanetMoon` state in params.
3. TTV is computed against orbit `t0` even though `t0` is time of periapsis, not transit ephemeris.
4. Observer clock offsets are incorrectly added to TTV values.
5. Native V4 stellar blocking/transit attenuation can double-count overlapping foreground occulters.
6. Reference-mode flux aggregation averages only top-level flux fields and leaves decomposition/debug fields inconsistent.
7. Forward/ring scattering phase is anchored to periapsis-style phase instead of transit/conjunction geometry.
8. `initApp()` is not idempotent and has no teardown path; repeated init can duplicate listeners, slider rows, and RAF loops.
9. Lesson changes wipe didactics response/comparison state too aggressively.

### Validation / contract gaps

10. Spectral-bandpass weight handling is under-validated and silently falls back to uniform weights on mismatch.
11. V3 and V4 higher-fidelity additive-composition contracts are not consistently enforced.
12. Mixed-shape transmission warning uses global one-shot state, reducing diagnosability across repeated runs.

### Docs / maintenance issues

13. `docs/params.md` is stale about where measurement and `clampSmearedFlux` logic live.
14. `README.md` still shows `config/` instead of `src/config/` in project layout.
15. Dead-code audit indicates likely retired or orphaned code:
    - `src/sim/v4/referenceWorker.ts`
    - `src/photometry/transitQuadraticLD.ts`
    - `src/app/didactics.ts: forceNextLessonStep`

### Phase 1: Fix bootstrap / DOM lifecycle correctness

#### 1.1 Non-DOM safe entrypoint

Fix path:

- move the dynamic import of `./app/bootstrap` inside the `document` guard in `src/main.ts`
- ensure importing `src/main.ts` in a non-DOM environment becomes a no-op instead of a crash

Test:

- import `src/main.ts` with no DOM globals and assert no throw and no bootstrap call

#### 1.2 Make UI refs runtime-bound instead of module-bound

Fix path:

- replace module-scope singleton `uiRefs` access with a runtime-created refs object, e.g. `createUiRefs()` or equivalent lazy getter
- resolve refs only after `renderAppShell(...)` has run
- thread the created refs into bootstrap wiring instead of importing a frozen singleton snapshot

Why this phase is necessary:

- it removes stale-node risk after shell re-render/remount
- it enables safe idempotence and teardown work in the next step

Test:

- remount or rebuild shell and assert listeners/refs bind to live nodes, not detached ones

#### 1.3 Add bootstrap teardown / idempotence

Fix path:

- introduce a disposer for `initApp()` side effects:
  - cancel active RAF loop
  - clear `quickApplyTimer`
  - detach event listeners registered in bootstrap and UI helpers
  - clear generated slider rows before rewiring
  - dispose or replace active runtime cleanly
- make repeated `initApp()` calls safe by disposing prior state first or refusing duplicate initialization with explicit cleanup

Test:

- call `initApp()` twice and verify:
  - one active RAF loop
  - no duplicated slider rows
  - one event response per click/change

Phase exit criteria:

- non-DOM import is safe
- bootstrap is idempotent
- refs are no longer a stale module-scope snapshot

### Phase 2: Fix UI param consistency and cleanup

#### 2.1 Moon disable cleanup ordering

Fix path:

- ensure moon structural state is resolved before moon-dependent photometry is read, or pass the resolved `moonEnabled` state into photometry readers
- when moon is disabled, explicitly remove moon-dependent photometry blocks such as `star.photometry.moonPhaseCurve`

#### 2.2 N-body cleanup when moon is disabled

Fix path:

  - the n-body checkbox is off, or
  - the moon is disabled

#### 2.3 Atmosphere / spectral input validation hardening

Fix path:

- validate `atmLambdaNm` and `atmTauScale` length compatibility earlier

Tests:

- disabling moon clears `moonPhaseCurve`
- disabling moon clears `nbodyPlanetMoon`
- malformed spectral UI inputs do not silently produce inconsistent runtime state

Phase exit criteria:

- param objects cannot retain moon-only state after moon removal
- UI photometry inputs round-trip into valid, structurally consistent params

### Phase 3: Fix timing semantics and O-C correctness

#### 3.1 Repair TTV reference semantics

Problem:

- `OrbitElements.t0` is explicitly periapsis passage, but TTV currently treats it as transit epoch

Fix strategy:

- introduce an internal transit-ephemeris reference helper for timing diagnostics
- compute TTV only relative to a valid transit reference epoch, not periapsis
- if a valid transit reference cannot be established for a configuration, return `undefined` rather than a misleading TTV value

Preferred implementation direction:

- derive a reference transit epoch from the same timing solver / geometry model used for the event estimate
- keep the fix internal to timing code rather than expanding the public UI schema unless required

#### 3.2 Keep observer clock offsets out of TTV

Fix path:

- update `applyClockOffsetToTiming(...)` so it shifts only absolute timestamps:
  - `planetTransitCenterSec`
  - `planetIngressSec`
  - `planetEgressSec`
  - `moonTransitCenterSec`
  - `moonIngressSec`
  - `moonEgressSec`
- leave `planetTtvSec` and `moonTtvSec` unchanged

Tests:

- eccentric or non-special orbit case where periapsis-based TTV differs from transit-based expectation
- observer clock offset changes absolute times but not TTV

Phase exit criteria:

- no timing diagnostic uses periapsis `t0` as a transit ephemeris shortcut
- TTV/O-C values are either correct or intentionally suppressed

### Phase 4: Fix native V4 overlap / visibility correctness

#### 4.1 Remove double-counting of overlapping occulters

Problem:

- native V4 currently sums pairwise overlap areas, which overblocks when foreground occulters overlap the same stellar region

Fix strategy:

- replace pairwise blocked-area summation with a union-aware visibility calculation
- use one deterministic visibility path for:
  - per-star visibility in `computeFluxBundle(...)`
  - non-stellar transit attenuation / `transitFactor`

Preferred implementation direction:

- reuse or extend native photometry visibility helpers instead of maintaining separate ad hoc area sums
- for partial-opacity/transmissive occulters, compose per-sample transmission or an equivalent deterministic visibility model that cannot exceed full blocking through double-counting

#### 4.2 Keep binary-lab and normal runtime behavior aligned

Fix path:

- ensure detached-binary stellar visibility and normal non-stellar blocking use the same overlap-safe contract where applicable

Tests:

- two overlapping foreground bodies in front of one star do not exceed physically plausible blocking
- regression test for `transitFactor` with overlapping non-stellar occulters
- detached-binary scenarios remain unchanged where they should

Phase exit criteria:

- overlapping occulters cannot deepen an eclipse/transit by double-counting shared area

### Phase 5: Fix reference-mode output consistency

Problem:

- reference mode averages scalar flux channels but keeps decomposition/debug state from only the last substep

Fix strategy:

- build an explicit reference-mode aggregation helper
- decide field policy once and apply consistently:
  - average flux scalars and decomposition channels
  - recompute debug fields derived from averaged flux
  - use the central sample for geometry/kinematics/timing if averaging those fields is not meaningful

Tests:

- reference-mode output remains self-consistent:
  - `flux.total` matches its decomposition contract
  - `debug.displayFluxValue` matches the aggregated flux contract
  - no last-substep leakage in averaged outputs

Phase exit criteria:

- reference-mode result is internally coherent, not a hybrid of averaged and last-substep state

### Phase 6: Fix photometry phase semantics and validation consistency

#### 6.1 Re-anchor scattering to conjunction/transit geometry

Problem:

- forward/ring scattering uses a periapsis-based phase proxy, which mis-phases the signal

Fix strategy:

- drive scattering by observer-star-body geometry or an explicitly conjunction-centered phase reference, not periapsis `t0`
- use one shared semantic definition across V3 and V4 paths

Tests:

- scattering peak tracks conjunction/transit geometry rather than periapsis
- V3/V4 parity remains valid under the new phase definition where expected

#### 6.2 Harden spectral-bandpass validation

Fix path:

- enforce weight-length compatibility with `lambdaNm`
- preserve correct index alignment when filtering invalid wavelengths
- avoid silent fallback to uniform weighting when the user supplied mismatched but non-empty weights

#### 6.3 Align higher-fidelity additive-composition rules across V3 and V4

Fix path:

- ensure native/scientific-browser V4 either:
  - rejects overlapping higher-fidelity additive channels the same way V3 validation does, or
  - explicitly disables conflicting channels in a documented and tested way
- prefer fail-closed validation over implicit stacking for scientifically sensitive combinations

#### 6.4 Scope mixed-shape warnings to runtime instance

Fix path:

- replace module-global one-shot warning state with per-runtime or per-call diagnostics so repeated simulations remain debuggable

Tests:

- validation rejects or normalizes invalid bandpass configurations deterministically
- higher-fidelity additive conflicts behave the same across V3 and V4 expectations
- mixed-shape warning behavior is deterministic per runtime / scenario

Phase exit criteria:

- scattering semantics are physically aligned with observer geometry
- validation behavior is explicit and consistent, not silent or mode-dependent

### Phase 7: Preserve didactics state more safely

Problem:

- changing lessons recreates runtime state and discards learner responses/comparison state too aggressively

Fix strategy:

- retain reusable didactics state on lesson switches where safe:
  - preserve response store
  - preserve comparison output unless the new lesson invalidates it
  - reset only lesson-position-specific learning state that truly must change
- if a hard reset is unavoidable, make it explicit in code and tests rather than accidental via full runtime recreation

Tests:

- switching lessons preserves response/comparison state when compatible
- incompatible lesson switches clear only the necessary subsets of state

Phase exit criteria:

- lesson changes are no longer an unintentional destructive reset of all didactic context
